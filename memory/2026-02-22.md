## Architecture Decisions (Confirmed 2026-02-22)

### Health Platform Integration
- **Only two platforms**: Apple HealthKit (iOS) and Health Connect (Android)
- **No Garmin support** - Garmin code in codebase is legacy/unused. Do not reference or build on it.

### Nostr Publishing
- **Kind 1301 events are NOT published to Nostr relays**
- Supabase is the single source of truth for workout data
- Kind 1301 events are constructed locally for structure/signing but only submitted to Supabase
- The `AUTO_COMPETE_FEATURE_ENABLED = false` flag is intentional

### Notifications
- **All push notifications must come from server-side** (Supabase edge functions → notify-user → Expo Push API)
- No client-side local notification triggers for background events
- **Notification overload concern**: A single workout (e.g., 5K run) could trigger 3-4 notifications (reward earned, competition leaderboard, workout synced, auto-joined). Need to be thoughtful about bundling/consolidating.
- Notification retry is acceptable on the server side (Supabase) but keep it simple

### Rewards / Payments
- **App does NOT handle payment delivery or retries**
- App submits workout data + reward tags (lightning address, team, charity) to Supabase
- An **external tool** (outside this codebase) reads Supabase data and zaps accordingly
- Payment retries, routing failures, etc. are handled by the external tool
- DailyRewardService only tracks rewards locally for UI display

## Invisible App Audit (2026-02-22)

Ran 5 parallel investigation agents across background sync, notifications, rewards, competitions, and Nostr publishing.

### What Works
- iOS HealthKit background detection (instant, event-driven)
- Android Health Connect periodic sync (15-min WorkManager intervals)
- Supabase workout submission + server-side auto-join competitions
- Reward tag generation (lightning address, team routing)
- Server-side push notifications for: reward earned, auto-joined competition, step reward
- Device token management (SHA256 npub hashing, per-user targeting)

### Known Gaps
- Background competition monitoring disabled (WebSocket crashes when app backgrounds)
- `LocalNotificationTrigger.notifyLeaderboardChange()` exists but never called
- No notification when background sync completes
- Fire-and-forget notification delivery (no server-side retry yet)
- `backgroundSyncService.ts` is deprecated (caused conflicts with active GPS tracking)
