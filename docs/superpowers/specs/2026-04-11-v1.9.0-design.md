# v1.9.0 Design Spec — Polish, Focus, and Trust

**Date:** 2026-04-11
**Branch:** v1.9.0 (to be created from v1.8.8)
**Theme:** Fix what's broken, remove what's unused, tighten what remains

v1.9.0 is a polish-and-focus release. The app is functionally close — this version fixes bugs that erode user trust, removes features that add clutter, and makes sure remaining features work correctly. The guiding principle is subtraction over addition.

---

## Phase 1: Rewards Backend Fixes

The most critical phase. Rewards are the core value proposition — users work out, earn rewards, rewards go where they chose. All three steps must work correctly.

### 1a. Fix Reward Routing

**Problem:** User's destination is set to PPQ.AI but rewards land in their personal wallet.

**Investigation area:** The `claim-reward` edge function (`supabase/functions/claim-reward/index.ts`) reads the destination from the workout submission. The routing diverges between LNURL-pay (for user wallets and charities) and bolt11 invoice (for PPQ.AI). If the PPQ bolt11 path fails silently, the function may fall back to the user's lightning address.

**Key files:**
- `supabase/functions/claim-reward/index.ts` (routing logic around line 1272+)
- `src/services/rewards/RewardDestinationService.ts` (destination address resolution)

**Fix:** Trace the full path from destination selection through to payment execution. Ensure PPQ.AI bolt11 path doesn't silently fall back to user's lightning address on failure. Add explicit error handling that fails the reward rather than misrouting it.

### 1b. Fix Reward Amount

**Problem:** User receiving 100 sats instead of the expected 50.

**Investigation area:** Base amount is 50 sats in both `src/config/rewards.ts:25` and the edge function. The 100 sats matches the Einundzwanzig bonus path (`DailyRewardService.ts:523`). Could also be streak bonuses doubling (2d +10%, 3d +20%, etc.).

**Key files:**
- `src/config/rewards.ts` (base amount config)
- `src/services/rewards/DailyRewardService.ts` (bonus logic, line 517+)
- `supabase/functions/claim-reward/index.ts` (server-side amount, line 1272)

**Fix:** Verify user isn't hitting the Einundzwanzig bonus path. Check streak bonus calculation. Ensure the amount passed to the edge function matches the intended 50 sats base.

### 1c. Remove Duplicate Notification

**Problem:** Two separate systems fire notifications for the same reward:
1. Edge function calls `notify-user` immediately after payment (line 1336-1364)
2. `RewardPollingService` detects the same payment ~45 seconds later and fires again

**Fix:** Remove the notification call from the edge function (`supabase/functions/claim-reward/index.ts` lines 1336-1364). Let `RewardPollingService` (`src/services/rewards/RewardPollingService.ts`) be the single notification source, handling deduplication client-side.

### 1d. Fix Sender Fallback

**Problem:** `getActiveSponsorName()` in the edge function falls back to "ALS Network" when no active sponsor is found (lines 41 and 43).

**Fix:** Change both fallback strings from `'ALS Network'` to `'RUNSTR'` in `supabase/functions/claim-reward/index.ts`.

### 1e. Fix Notification Copy

**Problem:** Notification currently says "100 sats sent to your wallet" — amount is wrong (tied to 1b) and language should be simpler.

**Fix:** Notification should read: **"Reward Received! You earned 50 sats"** (with correct amount from fix 1b). No destination mentioned.

## Phase 3: UI Restructuring

Larger layout changes to existing screens.

### 3a. Restructure History Page

**What:** Remove Journal and Habits filter tabs. Add a card at the top of the history view showing:
- **Today's step count** — pull from existing HealthKit step data already in the app (reuse existing source, don't create new HealthKit query)
- **Personal records** — best-ever numbers from workout history:
  - Longest Run (km)
  - Most Steps in a Day
  - Most Pushups in a session
  - (extend as more activity types have meaningful records)

This card replaces the separate stats screen. Stats become a visible, always-present summary rather than a hidden button.

**Key files:**
- `src/components/profile/tabs/UnifiedWorkoutsTab.tsx` (filter tabs, line 51-56)
- Existing step count data source (reuse)
- New component: `PersonalRecordsCard` or inline in the history view

### 3b. Redesign Rewards Screen

**What:** Replace current `EarningsHeroCard` with:
- **Top:** Hero number showing total all-time sats earned
- **Below:** List of destinations, each row showing:
  - Destination avatar image
  - Destination name
  - All-time total sats sent to that destination
  - Example: "PPQ.AI: 400" / "TheWildHustle: 150" / "Bitcoin Bay: 50"

Keep the destination picker (change button) and sponsor banner as-is.

**Key files:**
- `src/screens/RewardsScreen.tsx` (layout)
- `src/components/rewards/EarningsHeroCard.tsx` (replace or heavily modify)
- `src/services/rewards/SupabaseRewardService.ts` (`getRewardBreakdown()` — may need to query per-destination totals)

### 3c. Fix Strength Activity Grid

**What:** With squats removed in Phase 2, verify remaining 5 icons fit. If bench still overflows, adjust grid layout to wrap correctly.

**Key files:**
- `src/services/activity/ActivityGridService.ts`
- Activity grid rendering component

### 3d. Fix Feed Images

**What:** Change `SocialFeedPost.tsx` from forced square aspect ratio (`aspectRatio: 1`, `resizeMode: 'cover'`) to respecting the image's natural aspect ratio. Cap `maxHeight` to prevent absurdly tall images, let width fill the feed.

**Key files:**
- `src/components/social/SocialFeedPost.tsx` (image styling)

## Phase 4: Social Improvements

### 4a. Floating Post Button

**What:** Add a floating action button in the bottom-right corner of the Social tab. Label: "Post". Tapping opens the post composer.

**Style:** Consistent with app's black/orange minimal aesthetic. Positioned above the bottom tab bar.

**Key files:**
- Social tab screen (add FAB component)

**What:** When a user creates a post:

3. If Nostr publish fails, post still exists locally

**Key files:**
- Post creation flow
- Local post storage (AsyncStorage or existing local state)
- Nostr publishing service (kind 1 events)

## Phase 5: Events Improvements

### 5a. Fix Step Challenge Leaderboard

**Problem:** Step challenges show distance instead of steps on the leaderboard.

**Investigation area:** `ClubLeaderboardSection.tsx` checks `leaderboardMetric === 'steps'` (line 192) but may not be receiving the correct metric. The aggregation in `SupabaseCompetitionService.ts` (lines 768-848) may apply distance logic to step challenges.

**Key files:**
- `src/components/club/ClubLeaderboardSection.tsx` (display logic, line 192+)
- `src/services/competition/DailyLeaderboardService.ts` (step leaderboard builder, line 250-281)
- `src/services/competition/SupabaseCompetitionService.ts` (aggregation, lines 768-848)

**Fix:** Ensure competitions with `scoring_method: 'total_steps'` pass `leaderboardMetric: 'steps'` through to the display component, and that the aggregation queries `step_count` not `distance_meters`.

### 5b. Add Pushups to Event Types

**What:** Add a 5th event template to `SimpleEventCreationModal.tsx`:
- **Label:** "Pushup Challenge"
- **Activity type:** `pushups`
- **Scoring method:** `workout_count` or `total_reps` (needs investigation on what the backend supports)
- **Icon:** `fitness-outline`

**Key files:**
- `src/components/creation/SimpleEventCreationModal.tsx` (template array, lines 63-104)
- Grid layout adjusts from 2x2 to accommodate 5 templates
